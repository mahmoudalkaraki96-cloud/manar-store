# لوحة المنصة والمتاجر الجديدة

لوحة المالك: https://store-platform.mahmoud-alkaraki96.workers.dev/ . تسجيل الدخول عبر Cloudflare، والتحقق من توقيع الهوية داخل Worker أيضًا. ترتبط اللوحة بقاعدة store-platform-db فقط؛ لا ترتبط ببيانات منتجات أو زبائن أي متجر، ولا تحتوي على Cloudflare API token.

## إضافة متجر

1. اختر إضافة متجر، وأدخل الاسم والرابط المختصر. البريد والدومين الخاص اختياريان وقت التجهيز.
2. احفظ السجل ثم اختر بدء التجهيز من التفاصيل.
3. افتح مشغّل التجهيز، واختر Run workflow ثم operation=prepare على main. التشغيل يدوي حاليًا، ولا يوجد استطلاع دوري يستهلك حصّة Actions.
4. راقب عمليات التجهيز. لا تعني المسودة أو قائمة الانتظار أن المتجر منشور. تظهر الروابط والإصدار بعد نجاح الفحص الحي.

GitHub Actions يستخدم التوكن المحفوظ في أسرار المستودع وينشر SHA محددًا من platform/runtime-release.json. لا يقرأ منتجات متجر قائم لإنشاء متجر جديد. تتولد قاعدة tenant-<id>-db ومخزن tenant-<id>-media وواجهتان مستقلتان. تُحفظ معرفات الموارد ومراحل العمل قبل المتابعة، ولا يجري تبني قاعدة موجودة لمجرد تشابه الاسم.

## الفصل بين التهيئة والتحديث

منار وركن مسجلان management_mode=external. معالج إنشاء المتاجر يرفض إعادة تهيئتهما. تحديث متجر قائم يتبع خطة النشر والنسخ الاحتياطي المعتمدة في PLATFORM_OPERATIONS.md، ولا يشغّل استيرادًا تاريخيًا أو يعيد ضبط المخزون. Runtime الجديد1.2.1 في PR#89 منفصل عن main1.1.4 إلى أن تُحفظ إعدادات وأصول المتاجر القديمة.

## Red Rose

الاسم أزهار الوردة الحمراء — Red Rose، والمعرف red-rose. الواجهة: https://tenant-red-rose-store.mahmoud-alkaraki96.workers.dev/ . الإدارة: https://tenant-red-rose-admin.mahmoud-alkaraki96.workers.dev/admin . استُخدمت قاعدة وصور مستقلة، والكتالوج بدأ فارغًا.

بريد صاحب المتجر لم يُحدد. إدارة مؤقتة لمالك المنصة عبر Cloudflare، ولم تُولد كلمة مرور أو تُرسل بيانات دخول. تعيين حساب صاحب المتجر وربط دومينه وضبط شعاره وألوانه ومنتجاته خطوات تسليم لاحقة، وليست مكتملة تلقائيًا بمجرد إنشاء الموارد.

## التعافي

يعرض السجل مرحلة الفشل ورمزًا آمنًا. إعادة المحاولة تستأنف من معرفات الموارد المسجلة ولا تحذفها؛ لا يُعاد تطبيق baseline إذا اكتمل. يتوقف المشغّل عند عدم تطابق الهوية أو وجود بيانات غير متوقعة. إن تعطل runner بعد أخذ المهمة، يلزم مراجعة سجل GitHub وحالة lease قبل تعديل المهمة؛ لا تُنشئ موردًا بديلًا أو تحذف قاعدة لتجاوز الخطأ.

إن تعذر رفع artifact بسبب حصة GitHub، تبقى هوية قاعدة المنصة محفوظة في platform/control/resources.json ويُطبع معرف المورد غير السري في سجل bootstrap. لا يتضمن artifact أسرارًا. لا تُعد bootstrap إنشاءً جديدًا عندما يكون المعرف محفوظًا ومطابقًا.
