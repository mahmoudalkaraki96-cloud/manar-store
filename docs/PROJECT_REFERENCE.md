# Manar Store — Project Reference

> المرجع التشغيلي للمشروع. يجب تحديث هذا الملف مع كل تعديل بنيوي أو ميزة أو قرار نشر.

## 1. الهدف

متجر إلكتروني عربي (RTL) باسم **Manar Store** لمنتجات التوزيعات والهدايا والمناسبات، مع واجهة متجر ولوحة تحكم منفصلة.

## 2. الروابط والموارد

- المتجر: https://manarstore.ps
- لوحة التحكم: https://admin.manarstore.ps
- المستودع: `mahmoudalkaraki96-cloud/manar-store`
- الفرع الإنتاجي: `main`
- Store Worker: `manar-store`
- Admin Worker: `manar-store-admin`
- D1: `manar-store-db`
- R2: `manar-store-media`
- النشر: GitHub Actions → Cloudflare Workers

لا تُكتب مفاتيح API أو Tokens أو كلمات مرور في هذا الملف أو في المستودع. الأسرار تبقى في GitHub Actions Secrets وCloudflare فقط.

## 3. البنية التقنية

- Next.js 16 + React 19
- Vite/Vinext لبناء نسخة Cloudflare Workers
- TypeScript
- Cloudflare D1 لقاعدة البيانات
- Cloudflare R2 للصور والفيديو
- Drizzle schema/migrations
- واجهتان من المصدر نفسه: متجر ولوحة تحكم

### ملفات مركزية

- `worker/index.ts`: API، المصادقة، D1، R2 ومسارات Worker.
- `db/schema.ts`: تعريف جداول قاعدة البيانات.
- `drizzle/`: migrations تُنفذ مرة واحدة على D1.
- `app/admin/page.tsx`: الواجهة الرئيسية للوحة التحكم.
- `app/components/StoreHeader.tsx`: هيدر المتجر والبحث والحساب والسلة.
- `app/components/StoreHighlights.tsx`: عرض الهايلايت.
- `app/admin/HighlightsPanel.tsx`: إدارة واستيراد الهايلايت.
- `app/globals.css`: التنسيق العام والمتجاوب.
- `app/highlights.css`: تنسيق الهايلايت وصفحات المتجر الإضافية.
- `.github/workflows/deploy-cloudflare.yml`: البناء، migrations والنشر.

## 4. النشر

أي Push إلى `main` يشغّل:

1. `npm ci`
2. `npm run build`
3. `wrangler d1 migrations apply manar-store-db --remote`
4. نشر المتجر.
5. نشر لوحة التحكم.

لا يُعتبر التعديل منتهيًا قبل نجاح Build ونشر المتجر ولوحة التحكم.

## 5. قاعدة البيانات الرئيسية

المجالات الأساسية:

- الأقسام والمنتجات وصور المنتجات.
- المتغيرات والمخزون.
- المستخدمون والجلسات والعناوين.
- السلة/المفضلة حسب الواجهة والتخزين المستخدم.
- الطلبات و`order_items` والرسوم الإضافية.
- مناطق وأسعار الشحن.
- السياسات.
- إعدادات المتجر والسلايدر والنافذة المنبثقة.
- الهايلايت وأرقام صورها الثابتة.
- الزوار والمشاهدات.
- الموردون والمشتريات.

العلاقات التابعة للطلب تُحذف قبل الطلب عند عمليات التنظيف المتعمدة.

## 6. الحسابات والشحن

- تسجيل بالبريد وكلمة مرور، حد أدنى 6 محارف دون تعقيد.
- لا يوجد تأكيد بريد حاليًا.
- الحساب يدعم عدة عناوين.
- مناطق الشحن الافتراضية: الضفة 20 ₪، القدس 30 ₪، الداخل 70 ₪.
- الطلب يدعم رسوم توصيل إضافية موضحة للزبون.

## 7. الهايلايت

- تظهر أسفل الأقسام.
- حد النظام الحالي: 100 هايلايت.
- حد كل هايلايت: 200 صورة/فيديو.
- الفيديو: MP4/WebM حتى 50MB.
- الصور تُضغط إلى WebP قبل الرفع.
- رقم الصورة ثابت بصيغة `H{highlightId}-{imageNumber}`.
- العرض يدعم التقدم الزمني، الإيقاف، الفيديو والصور المصغرة.
- الاستيراد الجماعي من مجلد رئيسي: اسم المجلد الفرعي يصبح عنوان الهايلايت.
- الاستيراد يحفظ نقطة استكمال محليًا ويصدر تقرير CSV.

## 8. الصور والأداء

- بطاقات المنتجات والبحث تستخدم Thumbnail.
- الصورة الأصلية تُستخدم في صفحة المنتج/العرض الكامل.
- الصور البعيدة تُحمّل Lazy عند الاقتراب منها.
- الصور المرفوعة من لوحة التحكم تُضغط وتتحول WebP حيث ينطبق.
- ملفات R2 تُعرض عبر مسار `/media/`.

- الرفع يحفظ الأصل علىR2 ويولد نسخة WebP بعرض384. طلبات الصور للقوائم والبحث والسلة والإدارة تستخدم `/_media/thumbnail` بعروض256/384/640، وتُحفظ النسخ الناتجة علىR2 وتُخزن فيCache؛ الصور القديمة تُولّد عند أول طلب. الصورة الأصلية في صفحة المنتج.
- Images binding باسم `IMAGES` مطلوب في إعدادَي Wrangler للمتجر والإدارة؛ تمت إضافتهما في 2026-10-15.

## 9. SEO والتحليلات

- Domain Property موثقة في Google Search Console.
- `/sitemap.xml` و`/robots.txt` مستخدمان للفهرسة.
- Google Analytics 4 مربوط بالمتجر.
- أحداث المتجر تشمل: view_item، add_to_cart، begin_checkout، purchase.
- عداد لوحة التحكم الداخلي ليس بديلًا عن تقارير GA4.

## 10. سياسات المتجر

- التوصيل عادة خلال يوم إلى يومين وقد يزيد حسب الضغط.
- الاستبدال خلال يوم واحد.
- لا يوجد إرجاع.
- الإلغاء قبل خروج الطلب للتوصيل.
- مشاكل المنتج تُبلغ خلال ساعتين من الاستلام.
- رفض استلام الطلب يلزم الزبون برسوم التوصيل.
- إتمام الطلب يتطلب الموافقة على السياسات.

## 14. فهرسة وروابط المنتجات (2026-10-03)

- المسار `/product/{id}` يستخدم رقم المنتج الداخلي `products.id` فقط، وليس رقم الصنف، لمنع تعارض الروابط.
- `canonical` يُبنى من الأصل والمسار فقط دون query string أو hash.
- صفحات المنتجات غير الموجودة تحمل `noindex,follow` حتى لا تظهر كصفحات متجر مكررة في Google.
- صفحات المنتجات الصالحة تحمل metadata وProduct JSON-LD من D1 على مستوى Worker قبل إرسال HTML.
- `sitemap.xml` يستخدم روابط المنتجات الداخلية نفسها وتاريخ `updated_at` الحقيقي.

- تعرض لوحة الإدارة آخر رمز خطأ لاختبار الإشعار وتحدّث حالة الطابور كل5ثوانٍ أثناء فتح نافذة الإشعارات. رمز `push_network_error` يعني عدم تلقي رد HTTP من مزود الخدمة، لكنه لا يحدد وحده هل وقع الخطأ أثناء تجهيز الطلب أم الاتصال.
