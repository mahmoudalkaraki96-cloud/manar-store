# نشر تحديثات واجهات المتاجر

الحالة الحالية: منصة 0.4.0 منشورة، والمعاينة تعمل. الربط الفعلي ينتظر إذن Cloudflare؛ لا تنشر الواجهة نجاحًا قبل حفظ الهُوك والتحقق.

## الاستخدام بعد اكتمال الربط
1. افتح التحديثات واختر إصدارًا معتمدًا.
2. حدد متجرًا أو عدة متاجر أو كل المتاجر.
3. اضغط معاينة التحديث. النسخة الحالية والنسخة المستهدفة تظهر لكل متجر، والمتجر المحدّث يُتجاوز تلقائيًا.
4. اضغط نشر بعد مراجعة الأهداف، ثم تابع نتائج كل متجر في سجل العمليات.

الإصدارات المعروضة حاليًا تخص واجهة المتجر؛ لوحة الإدارة ليست ضمن النشر. لا migrations ولا إعادة تهيئة ولا نقل بيانات أو صور بين المتاجر.

## التشغيل الفني
- إعداد الإصدار من workflow platform-publisher.yml / prepare-release، بمصادر معتمدة وثابتة في scripts/platform-publish-prepare.mjs. لا يؤخذ source أو artifact من طلب المتصفح.
- الملفات المبنية في bucket خاص store-platform-releases، وبصماتها في manifest؛ تُحفظ نسخة manifest مع كل دفعة.
- مشغّل store-platform-release-runner على فرع platform/release-runner منفصل. إعداد setup لا يُشغل قبل الموافقة على Workers Builds Configuration Edit.
- قيمة توكن الإدارة في Build secret وحده، وWorkerاللوحة يحصل فقط على DeployHook محدود محفوظ كسرPLATFORM_RELEASE_BUILD_HOOK.لا توضعقيمأسرارفيالتوثيقأوالسجلات.
- الفحص يطابق DB/R2 واسمWorkerلكلمتجرقبلرفعالكود.تُفعّلالنسخةعبرWorkersVersions/Deploymentsلتجنبإعادةكتابةالدوميناتأوجداولالتشغيل.الإصدارالسابقمحفوظمرفقًابالهدف.
- فشل ما بعد التفعيل يحتاج مراجعة؛ لا تعاد محاولة تفعيل مجهولة النتيجة تلقائيًا. إلغاء من اللوحة متاح فقط قبل بدء التنفيذ.
- الربطالتلقائيالحاليلمنار/GitHubلميتغيربعد؛ينبغيضبطمساراتالنشرالتلقائيبعداكتمالالمشغّلحيثلايتجاوزتحديدالمتاجر.لاركنإعادةفتحللربطالتلقائي.
